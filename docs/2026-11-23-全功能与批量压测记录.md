## 2. 第二轮：量级压测

### 2.1 场景 1：突然写入 2000 个小文件

**操作**：`for i in $(seq -w 1 2000); do printf ... > bulk/$i.dat; done`（5.5 s 完成，共 7.8 MB）

**结果 A：规划极快**

```
同步规划完成 triggered_by="local-watcher" actions=2001 planner_ms=2 planning_total_ms=23
```

**结果 B：进程崩溃（P0）**

约 50 个文件后：

```
ERROR 未捕获 panic location=.../alloc/src/rc.rs:3781
      payload=unsafe precondition(s) violated: hint::assert_unchecked must never be called when the condition is false
thread 'tokio-rt-worker' (...) panicked at .../alloc/src/rc.rs:3781:13
thread caused non-unwinding panic. aborting.
```

非 unwinding panic → 进程 abort（开发版整条 `cargo tauri dev` 退出）。重启后续跑 80+ 未复现，属**竞态**。

**结果 C：吞吐崩塌**

重启后继续上传，日志中「收尾响应未回填 size，按本地快照补全」每 **5.5–5.8 s** 一条且严格串行：

| 指标 | 实测 |
|---|---|
| 单文件耗时 | ≈ 5.8 s（1 KB 文件同样） |
| 折算吞吐 | ≈ 620 个/小时 |
| 2000 个预计 | **≈ 3.2 小时** |

### 2.2 场景 3：突然删除几千个同步文件

**操作**：在 85 个已上传、1119 个排队中的状态下 `rm -rf bulk-test`（2000 个本地文件）

| 反应 | 实测 |
|---|---|
| 在途任务 | **255 条变 Failed「本地上传源不存在」**，`next_retry_at` 为空（不自动重试，符合预期） |
| 队列 UI | 只渲染 103 条，出现「有 95 项可以重试 / 重试全部」 |
| 计划器 | 随后 `actions=0`，`local=92 cloud=94 db=92` |
| **云端** | **一个都没删** |
| **本地** | 云端 82 个文件被**重新物化成占位符**（0 字节 + `com.hwcloud.fileId` + `com.hwcloud.size`）放回原目录 |

**结论：删除本地文件夹 ≠ 删除云端。** 删除意图被"云端→本地占位符"的镜像行为静默撤销，用户会看到删掉的文件夹自己长回来、里面全是 0 字节文件。而**单文件**删除是正常传播到云端的（F6 已验证），两者语义不一致。

### 2.3 场景 2 / 4：未能跑到达标量级

要造几千个占位符需先完成几千次成功上传（≈3.2 小时），且文件夹删除会被立即"复活"，根本走不到宽限期。**单文件宽限期逻辑本身已通过（F6）**，问题集中在批量/文件夹路径。

### 2.4 附带发现：队头阻塞导致"删除点了没反应"

队列清到 104 条后，右键 `bulk-test` → 删除 → 确认：**界面无任何变化，无任务、无报错、无提示**。日志：

```
INFO  上传源已变化，跳过 fileId xattr 写入 task_id=53 error=读取上传源失败：No such file or directory
WARN  远端写入核验暂不可用，保留歧义状态 task_id=53
WARN  action_filters: 已隔离尚有持久活动任务的同步动作 skipped=2 active=2
```

两个卡在"云端已写入、本地源消失"歧义态的任务，把**整个目录的删除动作永久隔离**；UI 既不显示"已阻止"，也不报错，用户视角就是"删除按钮坏了"。

### 2.5 附带发现：失败任务没有清理入口

94 条失败任务只有「重试全部」（会再失败一次），**没有取消/清除**入口；几百条脏任务只能等后台自行 `purged`。

## 3. 缺陷清单

| 编号 | 缺陷 | 严重度 | 根因/位置 |
|---|---|---|---|
| D1 | 2000 文件上传时进程 panic 并 abort | **P0** | `alloc/src/rc.rs:3781` `hint::assert_unchecked` 被违反（tokio worker 线程），疑为 `Rc` 跨线程/引用计数竞态；需 `RUST_BACKTRACE=full` 复现定位 |

| D4 | 歧义任务导致目录删除被永久隔离，UI 无提示 | P1 | `action_filters` 只打 WARN，未把"因活动任务被隔离"暴露到界面 |

| D6 | 重启后状态列整体错成「仅云端」 | P2 | `refreshBatchStatus()` 的 `mountConfigured` 竞态 + 无重试 + 空 catch |
| D7 | 上传结算后列表最长 60 s 才刷新 | P2 | 无结算后主动刷新 |
| D8 | 搜索未提交即显示「无匹配结果」 | P2 | 只按关键词渲染，未区分"未搜索/无结果" |
| D9 | 关于页 logo 不跟随 dev 展示名 | P3 | `useAppIdentity` 实例/时序 |
| D10 | 目录同步卡片「已投递 0 项」与实际任务数不符 | P3 | 计数未随投递更新 |
| D11 | 释放空间确认框路径溢出 | P3 | 缺少 ellipsis/wrap |
| D12 | 失败任务无取消/清除入口 | P3 | 队列只有"重试全部" |

## 4. 未覆盖项

| 项 | 原因 |
|---|---|
| 托盘菜单 60 s 不被刷新关闭 | 托盘是菜单栏额外项，AX `AXPress` 返回 `-25205`，合成点击受遮挡影响 |
| 虚拟滚动（>200 行） | 测试目录规模不足（深层仅 3 层、顶层 3 项） |
| 同名冲突三选一 | 无法在不污染数据的前提下稳定构造冲突 |
| 批量下载 / 批量释放 / 重命名 | 与单项用例同一套 IPC，本轮未重复跑 |
| 日志导出 | 会弹系统保存面板 |
| 场景 2 / 4（几千占位符、删+随机恢复） | 被 D1/D3 阻塞，无法造数 |

## 6. 结论

1. 单文件链路（上传 / 下载 / 释放空间 / 删除宽限期 / 队列 UI）是正确的，本迭代的新增能力在单文件规模下可用。
2. **量级一旦上千，客户端目前不可用**：会崩（D1）、会慢到不可接受（D2）、删除语义会错（D3/D4）。
3. 修复顺序建议：**D1 → D2 → D3/D4 → D5 → D6~D8 → 其余**。D1 需要先稳定复现拿到完整栈；D2 需要确认每个文件是否真的在等一次 5 s 轮询。

**环境限制（非产品缺陷）**

- 本机 CUA 会话中应用处于后台（`active=false`），合成鼠标坐标在后台应用上不生效；文件行是 `div` 点击区域，辅助功能树不可见。

  - D11：行宽改为跟随弹窗、路径 `min-width:0` + `text-overflow: ellipsis`。

**同轮发现并一并修复**

- 失败/卡住任务长期占用路径导致父目录删除被隔离：核验阶段「远端已确认但本地源已变化」不再无限重试，而是按已提交结算（基线记录任务快照）；下一轮 planner 会按本地当前状态重新规划。
- 文件列表 loading 遮罩可能永久停留（见上表最后一行）。
- 设置页导航与对话框缺少语义角色：`MateNavItem` 改为 `<button>`、`MateDialog` 增加 `role="dialog" + aria-modal + aria-label`，辅助技术可以访问导航与弹窗按钮。
