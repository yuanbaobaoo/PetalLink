# PetalLink v1.1.14

## 修复

- **同步引擎可能因「同路径重复基线」整体瘫痪，且已受损的安装现在会自动恢复**：
  - 现象：在同步目录里删除文件后放入同名新文件（或触发同名冲突处理）时，云端对覆盖上传会换发新的 fileId，而旧 fileId 的同步基线残留在本地数据库中，与新增基线形成同路径双记录。此后每个同步周期都拒绝继续规划，重启后同步引擎直接启动失败——**所有文件**停止同步，并反复提示冲突。
  - 引擎现在加载基线时自动收敛重复行：可信云端快照命中的身份优先保留，否则保留最近成功结算的非墓碑行，并在日志中记录裁决明细（`基线自愈：同路径重复基线已收敛`）。已受损的安装升级后首个同步周期即自动恢复，无需任何人工处理。
  - 上传/冲突结算写入新基线时，同步清理同路径旧身份残留行，从源头杜绝重复产生；用户主动删除的墓碑标记（防云端重建语义）不受影响。
  - 该缺陷本身不丢数据（云端与本地内容通常已一致），自愈也只整理同步账本，不触碰任何本地或云端文件。
- **传输队列的清空操作无法清除「已取消」任务**：清除条件此前只涵盖「已完成/失败」两种终态，漏掉了独立的「已取消」终态，导致已取消任务永远留在列表中。现已收敛为统一实现：「清除失败历史」升级为「清除失败与取消」，「清除完成+失败历史」升级为「清除全部已结束」（覆盖全部三种终态，绝不影响进行中的任务），菜单文案同步更新。

## 工程

- 清除传输历史的 SQL 收敛为 repository 层单一实现（`clear_terminal_transfers`），消除引擎与命令两条路径的重复语句。
- 新增 7 项回归测试：基线重复自愈 4 项（含真实故障库场景）、终态清除口径 3 项。

## 说明

- 平台与校验同 v1.1.13：macOS（Apple Silicon）与 Linux x86_64 AppImage 均支持应用内自动更新，全部资产附 SHA256SUMS 与 minisign 签名。
