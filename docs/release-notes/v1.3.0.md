# PetalLink v1.3.0

## 交互

- **目录同步记录并入任务队列**：目录「双端对齐」的作业不再独占一个分区，而是和上传/下载任务一起混排在同一个列表里——标签为「目录同步」，状态沿用排队中 / 正在规划 / 已投递 / 失败 / 已取消。四个筛选（全部 / 进行中 / 需要处理 / 已结束）、统计条计数与垃圾桶清除从此同时覆盖两类任务；进行中的作业置顶，避免它投递出的新任务行把自己挤到列表深处。
- **清除不再漏掉同步记录**：垃圾桶里「清除已完成 / 清除失败与取消 / 清除全部已结束」会同时清理传输历史与目录同步作业（新增 `sync_folder_clear`，与 `transfer_clear_*` 使用同一套开关）。此前清完传输记录后，弹层仍会挂着没有行级动作的「已投递」记录，而且统计条显示「全部 0」——这类自相矛盾的状态不会再出现。
- **失败的目录同步可重试、可放弃**：失败作业行内提供「重新入队」（同目录再次执行）与「取消」（落为已取消历史，不再自动重试）；失败汇总条的「有 N 项需要处理 / 重试全部 / 取消全部」也把失败作业计算在内，口径与筛选一致。
- **面板更名为「任务队列」**：面板标题、工具栏入口、队列相关 toast、README 与设计文档统一改名，避免一个面板里同时出现「传输队列」与「目录同步」两套叫法。
- **文案修正**：零差异的完成回执此前显示「已投递 0 项，在下方传输队列执行」，与事实不符，改为「两端已一致，无需传输」；有投递的完成回执改为「已投递 N 项，由传输任务继续执行」（两类行已在同一列表，不再有「下方」）。

## 修复

- **换账号后残留上一账号的目录同步记录**：登出 / 切换账号、清空缓存与旧 Linux 索引重置原本只清 `sync_items` 与 `transfer_queue`，`folder_sync_jobs` 会留下来，新账号打开任务队列就能看到上一个账号的「已投递」记录。现在三条清理路径一并清空作业表。
- **列表顺序与后端不一致**：前端合并两类任务时按 `created_at` 倒序排列，与 `transfer_queue` / `folder_sync_jobs` 的查询顺序保持一致；测试中依赖数组顺序的断言同步修正。

## 工程

- 新增 `sync_folder_clear(include_completed, include_failed)` 命令；`sync_folder_cancel` 允许取消失败作业（完成态仍不可覆盖）。
- 作业清除 / 失败取消 / 全量清空均有 Rust 单测；前端新增「混排与筛选计数、进行中置顶、失败行重试与取消、垃圾桶同时清理两类记录」组件测试。
- 无数据库 schema 变更（仍为 v7，只使用既有表与索引）。

## 说明

- 平台与校验同 v1.2.0：macOS（Apple Silicon）与 Linux x86_64 AppImage 均支持应用内自动更新，全部资产附 SHA256SUMS 与 minisign 签名。
- 已公开的历史版本仍不可变；本版本只影响之后发布的资产。
